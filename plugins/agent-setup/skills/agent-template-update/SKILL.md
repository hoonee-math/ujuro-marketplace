# agent-setup 플러그인 고치기

## 누가 고치는가

먼저 지금 사용자가 이 플러그인을 직접 고칠 수 있는지 확인한다.

- **고칠 수 있는 경우** — 플러그인 저장소의 작업 사본을 가지고 있고 그 저장소에 올릴 권한이 있다. 작업 사본에서 직접 고친다.
- **그 밖의 경우** — 고치지 않고 이슈로 알린다.

어느 쪽인지 모르면 사용자에게 묻는다. 설치된 플러그인 폴더(캐시)는 업데이트 때 덮어써지므로 어느 경우에도 고치지 않는다.

## 이슈로 알릴 때

1. 플러그인 `plugin.json` 의 `homepage` 에서 저장소를 찾는다.
2. 같은 내용의 이슈가 이미 있는지 확인한다.
3. 초안을 쓴다 — 어느 템플릿의 무엇이 문서와 어떻게 다른지, 근거 문서 주소, 확인한 날짜, 프로젝트에서 어떻게 고쳐 썼는지.
4. 초안을 사용자에게 보여 주고, 승인을 받은 뒤 등록한다.

## 직접 고칠 때

에이전트 하나가 `skills/agent-scaffold/templates/<이름>/` 폴더 하나다. 새 에이전트는 폴더를 더하면 되고 스크립트는 고치지 않는다.

1. **문서를 확인한다.** agent-setup 스킬의 "표준을 확인하는 방법"대로 그 에이전트의 현재 공식 문서를 읽는다.
2. **템플릿을 고친다.**
   - `template.json` — 만들 파일 목록(`path`, 내용을 가져올 `from`, 짧은 `description`, 공식 문서 `doc`), `.gitignore` 에 넣을 줄(`gitignore`), 문서를 확인한 날짜(`verified`).
   - 주석을 달 수 있는 형식의 파일에는 옵션의 짧은 설명과 공식 문서 주소, 기준일(`{{verified}}`)을 주석으로 넣는다. 주석을 지원하지 않는 형식에는 넣지 않고, 설명과 주소는 `template.json` 에만 둔다.
3. **기준일을 바꾼다.** `verified` 를 문서를 다시 확인한 날짜로 바꾼다. 문서를 확인하지 않고 날짜만 바꾸지 않는다. 확인했는데 바뀐 것이 없어도 날짜는 갱신한다.
4. **시험한다.** 플러그인 폴더에서 `node --test "**/*.test.cjs"` 로 시험을 돌리고, 임시 폴더에 실제로 만들어 결과를 본다. 동작이 바뀌었으면 시험을 함께 고친다.
5. **버전을 올린다.** 플러그인 `plugin.json` 과 마켓플레이스 목록의 버전을 함께 올린다.
6. **커밋한다.** 무엇이 왜 바뀌었는지와 근거 문서를 커밋 메시지에 적는다. 저장소에 올리는 것은 사용자에게 확인한 뒤에 한다.
