# agent-setup 플러그인 고치기

## 누가 고치는가

먼저 지금 사용자가 이 플러그인을 직접 고칠 수 있는지 확인한다.

- **고칠 수 있는 경우** — 플러그인 저장소의 작업 사본을 가지고 있고 그 저장소에 올릴 권한이 있다. 작업 사본에서 직접 고친다.
- **그 밖의 경우** — 고치지 않고 이슈로 알린다.

어느 쪽인지 모르면 사용자에게 묻는다. 설치된 플러그인 폴더(캐시)는 업데이트 때 덮어써지므로 어느 경우에도 고치지 않는다.

## 이슈로 알릴 때

agent-scaffold 스킬의 "서브에이전트를 띄울 때"대로 `issue-reporter` 서브에이전트에게 넘긴다. 넘길 것은 그 스킬 폴더의 `references/issue-report.md` 경로, 플러그인 저장소 주소(플러그인 `plugin.json` 의 `homepage`), 차이마다 어느 템플릿의 무엇이 문서와 어떻게 다른지와 근거 공식 문서 주소다.

- 차이가 템플릿과 공식 문서만으로 설명되면 사용자에게 묻지 않고 넘긴다.
- 사용자의 프로젝트 내용(경로, 코드, 이름 등)을 함께 적어야 설명이 되는 경우에는 먼저 본문을 보여 주고 승인을 받는다.
- 근거 공식 문서 주소가 없는 차이는 넘기지 않는다.

## 직접 고칠 때

에이전트 하나가 `skills/agent-scaffold/templates/<이름>/` 폴더 하나다. 새 에이전트는 폴더를 더하면 되고 스크립트는 고치지 않는다.

1. **문서를 확인한다.** agent-setup 스킬의 "표준을 확인하는 방법"대로 그 에이전트의 현재 공식 문서를 읽는다.
2. **템플릿을 고친다.**
   - `template.json` — 만들 파일 목록(`path`, 내용을 가져올 `from`, 짧은 `description`, 공식 문서 `doc`), 설정 파일의 키별 설명(`keys` — `key`, `description`, `doc`), `.gitignore` 에 넣을 줄(`gitignore`).
   - 주석을 달 수 있는 형식의 파일에는 옵션의 짧은 설명과 공식 문서 주소를 주석으로 넣는다. 주석을 지원하지 않는 형식에는 넣지 않고, 설명과 주소는 `template.json` 에만 둔다.
   - 날짜는 적지 않는다. 언제 무엇이 바뀌었는지는 저장소 이력과 이슈가 기록한다.
3. **시험한다.** 플러그인 폴더에서 `node --test "**/*.test.cjs"` 로 시험을 돌리고, 임시 폴더에 실제로 만들어 결과를 본다. 동작이 바뀌었으면 시험을 함께 고친다.
4. **버전을 올린다.** 플러그인 `plugin.json` 과 마켓플레이스 목록의 버전을 함께 올린다.
5. **커밋한다.** 무엇이 왜 바뀌었는지와 근거 문서 주소를 커밋 메시지에 적는다. 관련 이슈가 있으면 함께 적는다. 저장소에 올리는 것은 사용자에게 확인한 뒤에 한다.
