# 에이전트 설정 뼈대 만들기

템플릿은 만든 시점의 공식 문서를 옮긴 사본이라 낡을 수 있다. 뼈대는 바로 만들되, 커밋하기 전에 문서와 대조한다.

## 순서

1. **바로 만든다.** 사용자에게 묻지 않고 `node scripts/scaffold.cjs --dir <프로젝트 폴더>` 를 실행한다. 기본으로 템플릿이 있는 모든 에이전트의 파일과 `.gitignore` 규칙을 만든다.
   - 사용자가 에이전트를 특정했으면 이름을 인자로 적는다(예: `... claude`). 쓸 수 있는 이름은 `--list` 로 본다.
   - 사용자가 `.gitignore` 를 원하지 않으면 `--no-gitignore` 를 붙인다.
   - 공통 지침 파일은 어떤 에이전트를 골라도 만든다.
   - 이미 있는 파일은 덮어쓰지 않는다. `.gitignore` 는 있으면 끝에 블록을 덧붙이고, 다시 실행하면 그 블록만 갱신한다.
   - 실행 결과로 파일마다 설명과 공식 문서 주소가, 설정 파일은 키별 설명과 주소까지 나온다.
2. **만드는 것과 동시에 대조를 맡긴다.** 문서 확인을 기다리느라 만들기를 늦추지 않는다. 만든 에이전트마다 서브에이전트를 하나씩 병렬로 띄우고, 1번의 실행 결과(파일 목록, 설명, 키별 설명, 문서 주소)를 넘긴다. 서브에이전트는 그 에이전트의 현재 공식 문서를 읽어 다음을 근거 주소와 함께 보고한다 — 없어지거나 이름이 바뀐 것, 형식이 달라진 것, 설명이 문서와 달라진 것, 새로 권장되는 것.
3. **보고가 오면 프로젝트에서 고친다.** 생성된 파일을 프로젝트 안에서 고치거나 지운다. 설치된 플러그인의 템플릿은 고치지 않는다.
4. **사용자에게 안내한다.** 무엇을 만들었는지와 각 항목의 설명·문서 주소를 알린다. 대조에서 달라진 것이 있으면 템플릿의 설명이 아니라 문서 기준의 내용으로 안내하고, 무엇이 달랐는지 밝힌다.
5. **커밋한다.** 저장소가 아니면 초기화하고, 공통 설정만 담아 첫 커밋을 만든다. 대조와 수정을 끝낸 뒤에 커밋해서 커밋을 고쳐 쓸 일이 없게 한다.
6. **차이가 있었으면 이슈 등록을 서브에이전트에게 넘긴다.** 사용자를 기다리게 하지 않는다. 백그라운드 서브에이전트를 작고 빠른 모델로 띄우고, 끝나기를 기다리지 않고 사용자와의 작업을 이어 간다.
   - 넘길 것 — 템플릿과 공식 문서의 차이 목록, 차이마다 근거 문서 주소, 플러그인 저장소 주소(플러그인 `plugin.json` 의 `homepage`), agent-template-update 스킬의 "이슈로 알릴 때" 규칙.
   - 프로젝트 내용(경로, 코드, 이름 등)은 넘기지 않는다. 차이 목록은 템플릿 기준으로 적는다.
   - 서브에이전트가 끝나면 등록된 이슈 주소(또는 이미 있던 이슈 주소)를 사용자에게 한 줄로 알린다.
   - 템플릿을 직접 고치는 일은 여기서 하지 않는다. 사용자가 따로 요청하면 agent-template-update 스킬로 한다.
